# XSSscan v1.1.4

此版本汇总 v1.1.2～v1.1.4 的自动化回归、报告安全和 Chrome 页面请求预算优化，保留 Go 分层、四类 XSS 检测、现有 CLI 参数、报告 Schema 1.1 及 Windows EXE 支持。

## 改进

- v1.1.2：公开 Go 单元/浏览器/集成测试与本地合成靶场，建立 Windows/Linux 完整普通、race、vet、构建、三轮准确率/性能基线与日志门禁。
- v1.1.3：JSON、HTML、Markdown、SARIF、JUnit 默认统一脱敏；原始证据需显式 `--include-raw-evidence --output`。Unix 私有文件权限和 Windows 受保护 DACL 限制报告访问；截图默认不落盘，SDK 显式采集使用独立私有临时目录并随关闭/取消清理。
- v1.1.4：批次级并发安全计量器，浏览器 Fetch 请求阶段计量导航、重定向、同 target 子资源及异步 HTTP(S) 请求；超限先拒绝暂停请求、停止加载，再取消检查，保留不完整状态及诊断。完善 DOM 关闭竞争、调用期 Meter 继承和资源回收。

## 兼容性和预算边界

`--request-budget` 仍只限制 Go HTTP，默认 10000；`RequestsSent` 含义不变。新增 `--browser-request-budget` **默认 0、不限**，支持 YAML。仅显式配置正数时限制整批被守卫页面的获准请求尝试；不改变默认检测矩阵或减少验证。

**浏览器预算不是完整网络防火墙。** 它不保证计量/阻止独立 worker、ServiceWorker、SharedWorker、新窗口 target、Chrome 自主 favicon、预连接、更新/遥测、DNS/TLS、WebSocket 帧或 WebTransport 等流量。缓存命中、继续请求失败等使尝试数不同于 wire 请求/送达数；协议失败时应按不完整诊断处理。详见 [预算范围与验证](../../test/browser-budget-v1.1.4.md)。

默认报告脱敏不等于识别所有自由文本秘密/PII；终端日志仍需检查。显式 raw 文件包含凭据，不能公开分享。权限不防同用户进程或管理员；强制终止可能留下私有临时目录。详见 [安全说明](../../test/security-v1.1.3.md)。

## 发布包

| 平台 | 附件 |
| --- | --- |
| Windows amd64 | `xsscan_1.1.4_windows_amd64.exe`、`xsscan_1.1.4_windows_amd64.zip` |
| Linux amd64 / arm64 | `xsscan_1.1.4_linux_amd64.tar.gz`、`xsscan_1.1.4_linux_arm64.tar.gz` |
| macOS Intel / Apple Silicon | `xsscan_1.1.4_darwin_amd64.tar.gz`、`xsscan_1.1.4_darwin_arm64.tar.gz` |
| 校验与验收 | `SHA256SUMS`、`release-validation.json` |

压缩包包含程序、README、LICENSE、THIRD_PARTY_NOTICES 和 BUILDINFO.json；后者记录源码 SHA、Go 版本、架构和二进制 SHA256。Windows EXE 与 ZIP 内程序字节一致，Unix 归档保留可执行权限。每种架构须在对应原生 runner 上解压并运行验收，不以交叉编译成功冒充运行成功。候选流水线只上传 artifacts，不自动发布。

二进制未提供 Windows Authenticode 或 Apple Developer ID/公证，不承诺绕过操作系统来源提示。macOS 验收限于对应 CI 系统，不宣称覆盖所有旧系统。运行浏览器检测仍需兼容 Chrome/Chromium；五架构 CLI 产物验收关闭浏览器验证，浏览器完整回归由 Windows/Linux Regression 单独执行，不能混同。

## 发布门禁与复现

1. PR 合并前完成独立代码审查与 Windows/Linux 完整回归；每平台保留全部 1837 个历史身份（公共 1836 + 平台专属 1），新增测试正常通过。
2. 合并 master 后再次运行 Regression，并从同一 master SHA 运行 Release candidates。后者原生构建五架构，解压后检查 version/help、五格式安全负例、合成反射正例 exit 2（结构候选，不是执行证明）、HTTP 超限 exit 1；任何失败不得发布。
3. 下载实际候选，核对 BUILDINFO 源码 SHA、归档成员与权限、二进制及全部附件 SHA256，再从通过验收的 master 创建全新的 `v1.1.4` Tag。不得覆盖已有 Tag。
4. 生成 SHA256SUMS 和 release-validation.json，创建草稿并上传已验证附件；核对下载字节后才公开正式 Release。

运行原生候选验收：Go 1.26.9 在 PATH，工作区已提交且干净，执行 `python3 scripts/release_candidate.py --version 1.1.4 --goos <windows|linux|darwin> --goarch <amd64|arm64>`。系统/架构必须与 Go host 一致。所有运行靶场使用 loopback 和合成凭据，无外部扫描目标。

已完成的开发回归记录见 [CI 摘录](../../test/ci-v1.1.4.json)。正式发布的精确 master SHA、两条 CI 链接、原生运行记录及附件校验以 Release 的 `release-validation.json` 为准；没有原生验收结果的架构不得列为已验证。
